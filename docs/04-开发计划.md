# dsh-feishu 开发计划

## 33. 开发阶段总览

| 阶段 | 名称 | 目标 | 产出 |
|------|------|------|------|
| Phase 0 | 项目初始化 | 骨架代码可运行 | 可安装的空白插件 |
| Phase 1 | 认证 + 云盘核心 | 凭证安全存储 + 4 个 host tools | 云盘 CRUD 可用 |
| Phase 2 | 云盘 UI | Settings Card + 云盘 Tab | 完整云盘功能 |
| Phase 3 | 云文档 API | docx tools | 云文档 CRUD |

| Phase 7 | 发布 | GitHub + npm + dsh.so | 用户可安装 |

## 34. Phase 0：项目初始化

**预计时间**：1~2 天

> ⚠️ Phase 0 必须同时完成 6 个 P0 安全修复，不得拖到 Phase 1。

### 任务清单

**GitHub 基础设施**
1. [ ] 创建 GitHub 仓库 `dsh-feishu`
2. [ ] 配置 Branch Protection：`main` 分支 Require PR + 1 approval + CI
3. [ ] 创建 `.github/CODEOWNERS`：`* @your-username`
4. [ ] 创建 `.github/pull_request_template.md`

**项目骨架**
5. [ ] 初始化 `pnpm` 项目
6. [ ] 安装依赖：`@larksuiteoapi/node-sdk`、`@deepseek-ai/cordis`、`@deepseek-ai/schemastery`
7. [ ] 配置标准 `tsdown.config.ts`（`defineConfig`，不用 hostBundle/clientBundle）
8. [ ] 编写 `cordis.yml`
9. [ ] `pnpm build` 确认构建成功

**P0 安全骨架（含 6 项）**
10. [ ] `src/lib/client.ts`：`Map<profileId, Client>` 多 Profile 隔离
11. [ ] `src/lib/rateLimit.ts`：`RateLimiter` 接口框架（5 QPS）
12. [ ] `src/lib/pathGuard.ts`：`validatePath()` 白名单路径验证
13. [ ] `src/index.ts`：注册 dummy tool，host tools 用 `ctx.credentials.get()` 动态读取
14. [ ] `dsh plugin add ./dist/dsh-feishu-*.tgz` 本地安装测试
15. [ ] 确认 DSH 设置页出现插件入口

### 验收标准

```bash
pnpm build     # 成功
pnpm lint     # 无错误
lib/ 有正确产物 # index.js + index.d.ts + client/index.js
DSH 设置页 → 插件 → dsh-feishu 入口出现
```

## 35. Phase 1：认证 + 云盘核心

**预计时间**：3~5 天

### 35.1 任务清单

#### 认证模块
- [ ] `src/lib/client.ts`：基于 Phase 0 Map 架构，完善错误处理
- [ ] `src/lib/errors.ts`：统一错误类 + 飞书错误码映射（`99991401`/`99991664`/`230013`）
- [ ] `Config` schema：`appSecret: role('secret')` + 验证 App ID 格式
- [ ] 凭证安全验证：App Secret 不出现在 `dsh --dump-config` 输出

#### 云盘 Host Tools（5 个）
> ⚠️ 所有 tools 的 execute 闭包不捕获 config，每次从 ctx.credentials 运行时读取

- [ ] `feishu_verify_connection`：仅验证凭证（不含配额），入参只有 appId
- [ ] `feishu_get_quota`：单独工具查询云盘容量（`/drive/v1/files/stats`）
- [ ] `feishu_upload_file`：入参 localPath + folderToken，`validatePath()` 校验 + 流式上传
- [ ] `feishu_download_file`：入参 fileToken + savePath（savePath 同样白名单限制）
- [ ] `feishu_list_files`：出参明确 `fileToken` 字段
- [ ] `feishu_delete_file`：入参 fileToken

#### RateLimiter 实现
- [ ] `RateLimiter.acquire()` 令牌桶实现（5 QPS）
- [ ] 上传/下载/列表工具均通过 rateLimiter 保护

#### 凭证安全测试
- [ ] 填入 App ID/Secret，重启 DSH
- [ ] 执行 `dsh --dump-config > /tmp/cfg.txt`
- [ ] 确认 `appSecret` 值不在 `/tmp/cfg.txt` 中

### 验收标准

```bash
# Agent 可调用（工具名带 feishu_ 前缀）
feishu_verify_connection  # 返回 { success, message }
feishu_get_quota         # 返回 { used, total }
feishu_upload_file        # 上传 1MB 测试文件 → fileToken
feishu_list_files        # 列出文件，含 fileToken
feishu_download_file     # 下载刚上传的文件，校验内容一致
feishu_delete_file       # 删除测试文件

# 安全验证
dsh --dump-config 不含 appSecret 明文
```

## 37. Phase 3：云文档 API

**预计时间**：2~3 天

## 43. 风险识别

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| `@larksuiteoapi/node-sdk` SDK 有 bug | 低 | 高 | 改用原生 `fetch` 直接调用 |
| 飞书 API 行为与文档不符 | 中 | 中 | 边调边试，提前测试每个 API |
| Settings Card 组件踩坑 | 中 | 中 | 参考 dsh-config-manager 源码 |
| npm 发布审核被拒 | 低 | 低 | 先发 alpha/beta 版本 |
| 20MB 限制影响用户体验 | 高 | 中 | 在 UI 和 README 明确说明，引导压缩方案 |
